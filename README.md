# 学习通题库提取器 + 刷题台

一套用于 Microsoft Edge（Chromium 内核，Chrome 同样可用）的工具：

- **扩展**：在学习通（超星）的作业 / 考试页面自动识别题目、选项、答案与解析，存入本地题库
- **刷题站**：按章节 / 题型浏览，随机练习、即时判分、错题本与收藏复习

两者共享同一份数据格式规范（`site/js/core.js`），所以「抓到的题」和「刷的题」永远不会对不上。

---

## 隐私声明

**这个工具不联网。** 值得一提的几件事：

- 没有后端、没有埋点、没有统计。整个代码库里没有任何一次 `fetch` / `XMLHttpRequest` 发往外部服务器。
- 题目、答案、做题记录**全部只存在你自己的浏览器本地**（扩展用 `chrome.storage.local`，独立站用 `localStorage`）。
- 不接触你的账号密码。登录态完全靠浏览器自己的 Cookie 维持，扩展只读页面上的 DOM。
- 会发生的网络请求只有两类，都不携带你的任何数据：
  1. **题干里的图片**从超星自己的图床（`*.chaoxing.com`）加载 —— 图片本来就是题目内容的一部分。
  2. **独立站**（`site/index.html`）从 jsDelivr 拉一个 MathJax 文件用来渲染数学公式。断网时自动降级为纯文本，不影响做题。
- **扩展内置的刷题台不加载 MathJax**：MV3 扩展页面的默认 CSP 是 `script-src 'self'`，远程脚本会被浏览器拦掉，所以同步脚本会把这行剥掉。内置页里公式以原始文本呈现（`$x^2$` 原样显示）。想要渲染公式得把 MathJax 打包进扩展本地。
- `unlimitedStorage` 权限是为了让题库不被 5MB 配额卡住；`downloads` 用于导出 JSON；`contextMenus` 用于右键菜单；`activeTab` 用于弹窗读取当前标签页的 URL 判断是不是学习通页面。

### 权限为什么是这几个

发布前逐个核对过：每个权限在代码里都有实际调用点，没有「先申请着以后可能用得上」的。

| 权限 | 用在哪 | 不做行不行 |
|---|---|---|
| `storage` / `unlimitedStorage` | 题库存储 | 不行，这是核心 |
| `webNavigation` | `getAllFrames` 枚举 iframe | 不行，跨帧抓取依赖它 |
| `activeTab` | 弹窗判断当前页是不是学习通 | 不行，否则读不到非学习通页面的 URL，提示会变成「读不到当前标签页」 |
| `downloads` | 导出 JSON | 可以改成页面内 `<a download>`，但保留更稳 |
| `contextMenus` | 右键菜单抓取 | 可以去掉，属于便利功能 |

`host_permissions` 只覆盖 `chaoxing.com` / `chaoxing.com.cn` / `chaoxing.cn` 三个域，和 `content_scripts.matches` 完全一致。早期版本里有个 `*://*.edu.cn/*`，那会覆盖**所有高校站点**，而代码里一次都没引用过，已经删掉。

## 三、安装与使用

### 加载扩展

1. 打开 Edge，地址栏输入 `edge://extensions/`
2. 打开左下角「开发人员模式」
3. 点「加载解压缩的扩展」，选择 `chaoxing-quiz-tool/extension` 目录
4. 建议把扩展固定到工具栏，方便看徽标上的题目数

### 抓题

1. 正常登录学习通，进入**课程 → 作业 / 考试**的作答页或已批改页
2. 页面右下角会出现蓝色悬浮球，点开 →「抓取本题」
3. 如果作业是「一页一题」的分页形式，点「整卷翻页抓取」，它会自动翻页并累积到同一个题库
4. 也可以什么都不点 —— 默认开启自动抓取，进页面 1.5 秒后自动入库

### 刷题

- 扩展弹窗里点某个题库的「刷题」，或悬浮面板的「打开刷题台」
- 直接用浏览器打开 `site/index.html`（独立站模式，需要先导入 JSON）
- 独立站第一次打开可点「载入示例题库」体验功能，或导入 `site/sample-bank.json`

### 键盘快捷键（刷题台）

| 键 | 作用 |
|---|---|
| `A`–`H` / `1`–`8` | 选中对应选项 |
| `Enter` | 未提交 → 提交；已提交 → 下一题 |
| `←` `→` | 上一题 / 下一题 |
| `F` | 收藏本题 |
| `Space` | 显示答案（背题模式常驻显示） |
| `R` | 重做本题（清掉本次作答） |
| `Alt+Shift+S` | 在超星页面上抓取本题 |

## 四、题目数据格式

这是整个系统的契约。扩展抓取、存储、导出、刷题站导入，全部走这一套字段。

### 顶层结构

```json
{
  "schema": "chaoxing-quiz/v1",
  "exportedAt": "2026-09-21T14:45:00.000Z",
  "generator": "chaoxing-quiz-tool",
  "stats": { "banks": 2, "questions": 15 },
  "banks": [ /* Bank[] */ ]
}
```

`schema` 是版本号。字段发生破坏性变更时递增，导入器会告警但仍尽力解析。

### Bank（题库 = 一套作业 / 一次考试）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，格式 `courseId::workId`。**分页抓取靠它累积到同一个题库** |
| `courseId` | string | 课程 ID，来自 URL |
| `courseName` | string | 课程名，来自页面 DOM |
| `workId` | string | 作业 / 考试 ID |
| `workTitle` | string | 作业标题 |
| `kind` | `"work"` \| `"exam"` | 作业还是考试 |
| `createdAt` / `updatedAt` | ISO string | 时间戳 |
| `questions` | Question[] | 题目列表 |

### Question（题目）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | **稳定 ID**，见下方说明 |
| `type` | enum | `single` / `multiple` / `judge` / `fill` / `short` / `other` |
| `index` | number | 在题库里的原始题号（仅用于排序展示，不参与身份识别） |
| `stem` | string | 题干纯文本（用于去重、搜索、无障碍） |
| `stemHtml` | string | 题干富文本，保留图片与公式排版 |
| `options` | Option[] | 选项；填空题为空数组 |
| `answer.keys` | string[] | 选项键，如 `["A","C"]`。选择题 / 判断题用 |
| `answer.text` | string[] | 文本答案。填空题按空序排列，简答题为参考答案 |
| `answerRaw` | string | 答案原文，保留用于人工核对与重新解析 |
| `analysis` | string | 答案解析 |
| `score` | number \| null | 分值 |
| `hasAnswer` | boolean | **答案是否已公布**。为 `false` 时刷题台会标注并跳过判分 |
| `chapter` | string | 章节名，来自页面面包屑；参与章节筛选 |
| `courseId` / `workId` / `courseName` / `workTitle` | string | 冗余存储，方便题目单独导出后仍能追溯来源 |
| `sourceUrl` | string | 抓取页面的 URL |
| `origin` | string | 源站 origin，用于把题干里的 `/star3/xxx.png` 相对路径补成绝对地址 |
| `capturedAt` | ISO string | 抓取时间 |

### Option（选项）

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | `A`–`H` |
| `text` | string | 选项纯文本 |
| `html` | string | 选项富文本 |
| `correct` | boolean | 抓取时若能识别出「这是正确选项」则置 true（仅作线索，标准答案以 `answer` 为准） |

### 学科分类

一个人可能同时在上好几门课。题库里的题如果不分学科，全都堆在一起根本没法练。

分类的**原始依据是题库自带的 `courseName`**（超星的课程名），不用手动标。
但超星的课程名往往长成 `2024-2025-1-高等数学(上)-0001` 这种，没法看，所以还得能改名。

改名**不写在题库上**，而是记一张 `courseId → 学科名` 的映射表：

```
subjects = { "1234567": "高等数学", "8901234": "大学英语" }
```

这样做的原因是：同一门课会不断抓来新题库（每章一次作业），
映射表能让新抓到的自动归位，不用每来一次就改一次名。

解析顺序（`CQB.subjectNameOf`）：

```
映射表里有没有这个 courseId？
  ├─ 有 → 用它（用户改的名字）
  └─ 没有 → 用题库自带的 courseName
              └─ 也是空 → 「未分类」
```

几个边角情况：

| 情况 | 处理 |
|---|---|
| 抓不到 `courseId` | 退回用题库 id 当映射键（`CQB.subjectKeyOf`），否则这些题库永远改不了名 |
| 同一门课有两三个 `courseId`（高数上/高数下） | 改成同一个名字后自动并成一组 —— 归组按**名字**而不是 id |
| 想改回自动识别 | 改名时留空即可，映射表条目被删掉，退回用 `courseName` |
| 「未分类」 | 永远排在学科列表最后，不跟正式学科抢位置 |

筛选走 `Session.buildPool(banks, { subjects: ['高等数学'], subjectMap })`。
传的是**名字数组**而不是 id —— 用户是按「高等数学」这个概念选的，不是按 courseId。

### 导入的题目怎么归类

抓来的题自带课程名，不用管。**导入的题不一样** —— 外部的 JSON / 文本里没有课程名，
默认会全部落进「未分类」。三个入口：

| 入口 | 位置 | 适合 |
|---|---|---|
| **导入时指定学科** | 导入弹窗里的「这批题属于哪个学科？」 | 正常情况，一次到位 |
| **整理题库**（逐套指定） | 侧栏「学科」那一行的「归类」 | 一批导入的题其实横跨好几个学科，得一套套拆开 |
| **改名** | 侧栏「学科」那一行的「改名」 | 整个学科统一换个好记的名字 |

「整理题库」里未分类的题库排在最前面（它们才是最需要处理的），支持搜索和
「应用到全部」批量填。**取消不落盘**，重新打开会恢复原值。

### 文本导入的题库 id 不能再是常量

`parseText` 原来把题库 id 写死成 `'bank::text-import'`，于是**所有文本导入全并进同一套题库**。
后果是：不管你分几次导入、导的是哪门课，它们都是一套，归类功能根本没有粒度可用。

现在 id 由题干指纹决定：

```js
id = 'bank::text::' + CQB.hash64(所有题干拼起来)
```

- 同一批文本重复导入 → id 相同 → 合并，保持幂等，不会产生重复题库
- 不同批次的文本 → id 不同 → 各自成库，可以分别归类

题库名也从写死的「文本导入题库」改成带第一题影子的「文本导入 · 资本积累的源泉是？」，
否则归类列表里一排一模一样的标题，分不清谁是谁。导入弹窗里也可以直接指定题库名
（只在本次只导入一套时生效 —— 一次导多套还硬套同一个名字只会更乱）。

### 稳定 ID 的生成规则

```
id = "q_" + hash64(courseId + "|" + type + "|" + normalizeText(stem))
```

**刻意不包含题号。** 因为超星的分页作业每次只加载一页，题号在不同次抓取里会漂移
（尤其乱序出题时）。用「课程 + 题型 + 归一化题干」做键，同一道题无论从哪一页抓到，
算出的 ID 都一样，才能正确去重和累积。

`normalizeText` 会剥掉零宽字符、全角空格、以及题干开头的「1、」「2.」之类前缀。

### 合并规则（同 ID 撞车时）

1. 用「信息量评分」决定保留哪一份：**有答案 > 有解析 > 有选项 > 题干更长**
2. 落选那份的非空字段用来补齐胜出者的空字段
3. **ID 始终沿用已存在的那一个**，否则用户的练习进度会对不上号

典型场景：第一次抓取时老师还没放答案（`hasAnswer: false`），到期后重新抓一次，
新数据自动覆盖旧数据并补上答案，题目在错题本里的记录不受影响。

## 五、交互流程

### 抓题流程

```
进入作业页
   │
   ├─ content.js 启动 → 检测登录态 ──未登录──▶ 面板提示「请先登录」，不抓取
   │
   ├─ MutationObserver 监听 DOM ─┐
   ├─ history.pushState 钩子 ────┤ 任一触发 → 1.2s 防抖
   │                             ▼
   │                      extractor.scanDocument()
   │                             │
   │             ┌───────────────┴───────────────┐
   │             ▼                               ▼
   │      TOP 帧解析到题目                TOP 帧为空（题在 iframe）
   │             │                               │
   │             │                     后台 scanAllFrames() 挨个问
   │             │                               │
   │             └───────────┬───────────────────┘
   │                         ▼
   │              题干哈希签名比对 —— 与上次相同则跳过
   │                         ▼
   │            CAPTURE 消息 → service-worker
   │                         ▼
   │      mergeIntoBank()：双重去重（ID + 题干指纹）→ 写入 chrome.storage
   │                         ▼
   │              徽标更新 / 刷题台 storage.onChanged 实时刷新
```

### 刷题流程

```
载入题库（GET_BANKS 或 localStorage）
   │
   ├─ 左栏：选题库 → 状态/题型/章节筛选 → 生成题目池
   │         │
   │         └─ 模式：顺序 / 随机(Fisher-Yates) / 背题(直接显示答案)
   │                 状态：全部 / 未做 / 已做 / 错题 / 收藏
   ▼
渲染当前题（题干富文本 + 选项；填空题按空数生成输入框）
   │
   ├─ 选择 → 暂存到 session.answers（切题不丢）
   ▼
提交 → core.grade()
   │
   ├─ 选择题：集合相等才算对（多选少选都算错，与学习通一致）
   ├─ 判断题：先按选项文本把「对/错」映射成真实选项键，再按集合比
   ├─ 填空题：去空白、忽略大小写逐空比对，给出命中百分比
   ├─ 简答题：不自动判分，只展示参考答案
   └─ hasAnswer=false：返回 ungraded，不计入进度、不污染错题本
   │
   ▼
写入 progress（试答次数 / 错次 / 最后答案 / 收藏 / 错题标记）
   │
   └─ 答错 → 自动进错题本；答对 → 自动移出（可在设置里关掉）
```

### progress 结构（存在 localStorage，与题库解耦）

```json
{
  "<questionId>": {
    "attempts": 3,
    "wrong": 2,
    "lastCorrect": false,
    "starred": true,
    "wrongBooked": true,
    "lastAnswer": { "keys": ["B"], "text": [] },
    "updatedAt": "2026-09-21T15:02:11.000Z"
  }
}
```

分开存的原因：题库是「从哪来的数据」，进度是「我练到哪了」。
清空题库不该丢进度，换台设备也不影响。

## 六、边界情况处理

| 场景 | 处理方式 |
|---|---|
| **登录态保持** | 完全依赖浏览器 Cookie，扩展不接触、不存储账号密码。`checkLoginState()` 从域名、登录框元素、页面文案三处判断是否掉线，掉线时明确提示而不是抓出一个空题库。跨 frame 请求由浏览器自动带 Cookie。 |
| **题目在 iframe 里** | `all_frames: true` + `match_about_blank: true`。每个 frame 独立扫描；TOP 帧为空时后台用 `webNavigation.getAllFrames` + `frameId` 逐帧发 `DO_SCAN`，汇总后统一合并。**自动抓取也走这条路**：顶层帧扫不到题目时（章节页、内嵌作业的常态）会主动向后台要一次跨帧汇总，而不是直接放弃。 |
| **切「章节测验」这类页内标签** | 题目所在的 iframe 会被换掉 `src`，这是属性变化不是节点变化。`MutationObserver` 额外监听 `attributeFilter: ['src']`，否则切标签后不会重新扫描。更根本的办法是**扩展自己去点那个标签** —— 见下方「自动打开章节测验」。 |
| **点错标签跳到别的章节** | 超星左侧目录树里每个章节都挂着一个写着「章节测验」的条目，文案和真标签一模一样。所以不能只靠文案匹配：候选必须和「视频」标签**待在同一个标签栏容器里**（同父节点，或父节点互为兄弟）。已经处于激活态的标签也会被跳过。`tools/tab-test.mjs` 专门用带诱饵的夹具锁死这条规则。 |
| **自动切换来回弹** | 切到测验页抓到题 → 切回视频页 → 视频页又没题目 → 再切过去…… 无限循环。用 `sessionStorage` 按 URL 记「这个地址已经自动切过一次」，而 URL 变了（换到下一个章节）仍会自动生效。 |
| **章节测验还没解锁** | 超星要求先完成视频任务点。切过去后连试三次没题目、且页面文案含「请先完成 / 任务点未完成」时，立刻切回并说明原因，不会干等 20 秒。 |
| **没有「下一题」按钮** | 章节测验、单页作业、已翻到最后一页都是这样。此时「整卷翻页抓取」**退化为一次性抓取当前所有 frame 的题目**，而不是报个错什么都不抓。 |
| **顶层帧和 iframe 的 URL 参数不一致** | 顶层地址栏常只有 `courseId` 没有 `workId`（章节页就是如此），而 `workId` 决定了题目归到哪个题库。上下文按字段逐个补齐，空缺的从别处取，**不整体覆盖** —— 否则一份空值会抹掉另一份的有效值。 |
| **用户分不清独立站和内置站** | 独立刷题站（`site/`）读的是本页 localStorage，和扩展的 `chrome.storage` 是两套存储，**互不相通**。独立站空状态会明确标注这一点并指向正确做法（从扩展弹窗点「打开刷题台」）。 |
| **抓不到题目说不清原因** | 面板和弹窗都有「诊断」按钮：列出每一个 frame 的 URL、是否注入了脚本、解析出几道题、有没有下一页按钮、题库 ID，以及题库总量和自动抓取开关。这类问题在本地复现不了，只能把事实摊开。 |
| **SPA 换页不刷新** | 劫持 `history.pushState` / `replaceState` 并监听 `popstate`，触发重新扫描。 |
| **DOM 异步渲染** | `MutationObserver` 监听 `childList + subtree`，1.2 秒防抖后再扫描，避开动画期间的半渲染状态。 |
| **一页一题的分页作业** | 「整卷翻页抓取」会一路点到没有「下一题」按钮为止，中间遇到空页、慢页都不停。详见下方「翻页抓取为什么容易抓不全」。中止条件只有四个：按钮消失/变灰、连续 2 次点击后页面无变化、撞到 300 页上限、用户手动停止。**绝不无限循环。** |
| **翻页时页面先清空再填充** | 超星是两段式渲染：先显示「加载中」占位符，一两秒后才填入题目。稳定窗口按「页面上有没有题目块」动态取：有题目块只需 500ms 确认，还没有就等 2000ms；页面上有加载遮罩则完全不算稳定。 |
| **「下一题」按钮在 iframe 里** | 后台先探测每个 frame 有没有按钮，把翻页循环交给「握着按钮的那个帧」执行；跨域 iframe 顶层碰不到，这套机制是必需的。 |
| **翻页任务中途想停** | 面板上有「停止抓取」按钮，已抓到的题目会保留。MV3 的 service worker 单个事件有 5 分钟上限，所以翻页用「立即返回 + 完成回调」模式，不挂长连接。 |
| **同一页重复抓取** | 两道去重：① content 侧按题干哈希缓存已上报项；② 后台 `mergeIntoBank` 幂等，重复合并只会 `added: 0`。 |
| **跨批次 ID 漂移** | 某批 payload 缺 `courseId` 时 ID 会变，导致题库出现重复题。除 ID 外再做一层**题干指纹**去重；同时用题库自身的 `courseId` 作为缺失字段兜底。读盘时 `dedupeBanks()` 还会清理历史脏数据。 |
| **答案尚未公布** | 解析不到答案时置 `hasAnswer: false`，绝不用「我的答案」冒充标准答案。刷题台标注「答案未公布」、判分返回 `ungraded`、不计进度；设置里可整体跳过这类题。 |
| **判断题选项顺序颠倒** | 不硬编码 `A = 对`。拿答案里的「对/错」去比对选项文本内容，实在匹配不上才退回位置约定。 |
| **多选漏选 / 多选** | 按集合完全相等判分，与学习通的评分口径一致。 |
| **填空题多空** | 空数取 `max(题干中 ____ 个数, 答案个数, 1)`。解析「第一空：x 第二空：y」「x；y」两种写法。 |
| **打乱选项后判分错乱** | `Session.shuffleOptions()` 在重排选项的同时重映射 `answer.keys`，返回新对象不改原题。冒烟测试里跑 40 次随机打乱验证答案始终指向原本正确的选项文本。 |
| **题干里的 `<` `>`** | 富文本判定用**白名单标签正则**而非 `<[a-z]+>`，避免「若 a<b 则」被当成标签解析后正文丢失。 |
| **抓来的 HTML 注入** | `sanitizeHtml()` 标签白名单 + 剔除所有 `on*` 事件 + 拦 `javascript:` 协议 + 去注释节点。题库来自网页，理论上可信，但不给它执行的机会。 |
| **题干里的图片** | 超星常用 `/star3/xxx.png` 相对路径。存下 `origin`，渲染时补成绝对地址；加载失败自动隐藏，不留破图。 |
| **数学公式** | 优先保留 `stemHtml`，刷题台加载 MathJax 渲染 `$...$`。离线时静默降级为原始文本，不报错。 |
| **MV3 后台随时被杀** | service-worker 里**零内存状态**，每次收到消息都现读现写 `chrome.storage`。导出用 data URL 而非 Blob URL（SW 回收后 Blob URL 会失效）。 |
| **多 frame 并发写入** | 所有写入收归后台一处。同 ID 合并幂等，最坏情况是同一题被合并两次，不会丢数据也不会重复。 |
| **题库过大** | `permissions` 里带 `unlimitedStorage`，绕开 localStorage 5MB 限制。进度写入做 150ms 防抖，避免连续答题卡顿。 |
| **超星改版导致抓不到** | `extractor.js` 顶部集中了 `SEL` 选择器表，每类信息给多组候选。改版时只改这张表，不用动逻辑。 |

## 七、自动打开章节测验

超星的章节页把测验藏在页内标签里（`1 视频 | 2 章节测验`），不点开题目根本不会加载。
所以「打开章节页就自动抓题」这件事，光靠扫描是做不到的 —— 必须有人去点那个标签。

扩展的做法是：**自动切过去、抓完、再切回来**，用户什么都不用做。

```
章节页打开
   │
   ├─ 扫本帧 → 没有题目（视频页）
   ├─ 跨帧汇总 → 还是没有题目
   │
   ├─ 找「章节测验」标签 ──找不到──▶ 放弃（不能乱点，见下）
   │        │找到
   │        ▼
   ├─ 记下「要切回哪个标签」，写入 sessionStorage
   ├─ 点开章节测验
   │        │
   │        ├─ 每 2 秒查一次 ──拿到题目──▶ 入库 → 1.2 秒后切回原标签
   │        ├─ 三次都没题 + 页面说「请先完成任务点」 → 立刻切回并说明
   │        └─ 最多等 20 秒 → 切回
   ▼
结束（同一个 URL 只做一次，换章节后重新生效）
```

### 最大的风险是点错东西

页面上到处都有「章节测验」四个字 —— 左侧目录树里**每个章节都挂一个**。
点中目录里的那个，用户就被带到别的章节去了。所以候选要过两道关：

1. **文案必须干净**：允许「2」「2.」这样的序号前缀，但 `课程视频` 这种带前缀的不算
2. **必须和「视频」标签在同一个标签栏里**：同父节点，或父节点互为兄弟
3. 已经是激活态的标签直接跳过

这三条规则用 `tools/tab-test.mjs` 的带诱饵夹具锁死。四个场景：

| 场景 | 期望 |
|---|---|
| 停在视频标签、没有题目 | 自动切换 → 抓取 → 切回，**且只切一次** |
| 章节测验已经开着 | 一次都不点，直接抓当前页 |
| 没有标签栏，只有目录诱饵 | `findQuizTab()` 返回 null，一次都不点 |
| 用户关掉了这个功能 | 一次都不点 |

面板底部的「自动开标签」和扩展弹窗里都有开关，默认开着。

### 为什么抓完默认「切回原标签」而不是「切到下一节」

因为这两件事的语义完全不同：

- **切回**是单页抓取。用户大多数时候是真的在看视频，抓题只是顺手。
  如果抓完把人送到下一节，他会失去视频进度位置 —— 那比不做还烦。
- **切下一节**是批量采集。它天然会连锁：切到下一节 → 那节也没题目 →
  再切下一节…… 一路跑完整章。

把后者设成默认，等于**用户随手打开任何一节都会触发整章自动跑一遍**。
这是在对超星连续发请求，跑多久、跑多少，用户完全没概念也没同意。
所以它必须是显式动作。

### 连续采集本章

面板上的「连续采集本章」按钮（扩展弹窗里也有）。行为：

```
点「连续采集本章」
   │
   ├─ 当前节：有题就抓；没题就看有没有「章节测验」标签，点开它再抓
   ├─ 本节没测验（连标签栏都没有）→ 跳过，只等 1.6 秒
   ├─ 抓到一节 → 等 4 秒 → 点「下一节」
   ├─ 按钮变成「下一章」= 到章末 → 停（不跨章）
   ├─ 点了「下一节」页面没变化 → 停（按钮其实是禁用的）
   └─ 走满 40 节 → 停
```

几处刻意加的安全阀：

| 机制 | 防的是什么 |
|---|---|
| 最多 40 节 | 跑飞 |
| 节间固定 4 秒 | 别把超星惹毛，也给自己留出抓取时间 |
| 本章结束就停，不跨章 | 跨章导航结构差异大，容易跑进奇怪的页面 |
| 点完没变化就停 | 最后一节的按钮可能只是变灰但还在 |
| 面板上的「停止抓取」 | 随时叫停，已抓到的题目都保留 |
| 同一节只推进一次 | 「抓到了」可能被两条路径各通知一次（观察器 + 轮询），不去重会跳节 |

「本节是否已处理」用的是 `小节标题` 而不是 URL —— 有些超星页面切小节时 URL 根本不变，
只换 iframe，只看 URL 会误判成「还是同一节」。

### 「下一节」按钮为什么那么难认

用户报过「有时候点了连续采集本章，说找不到『下一节』然后直接停」。
追下去发现识别条件太严，同一件事有六种写法：

| 写法 | 例子 | 原来的问题 |
|---|---|---|
| 普通 | `<a>下一节</a>` | 正常 |
| 带箭头 | `<a>下一节 ›</a>` | `^下一节$` 匹配不上 —— **这是失败主因** |
| 只有图标，文字在 title | `<a title="下一节"><i>›</i></a>` | 原来只读 `textContent` |
| 只有类名，完全没文案 | `<a id="nextNode" class="nextNode">` | 原来完全没有兜底 |
| hover 才显示 | `visibility: hidden` | 被可见性检查整个滤掉 |
| 章末 | `<a>下一章 ›</a>` | 要认出来并**停**，不能跨章 |

现在分四层降级：**文案（含 title/aria-label）→ 类名兜底 → 目录树 → 放弃**。
匹配前先把箭头类装饰字符剥掉；按钮只要「有盒子」就算，不管它是不是 hover 才显示
（`display:none` 的照样会被尺寸检查挡掉，所以「已经是最后一节」仍然识别得出来）。

另外两点：

- **不再一次失败就收工。** 找不到时重试 4 次、每次隔 1.5 秒 ——
  翻页按钮可能是懒渲染的，页面刚切完还没稳定。之前上来就判死刑，
  用户看到的就是「点一下就停」。
- **失败信息要能定位问题。** 面板和弹窗的「诊断」现在会列出每个框架识别到的
  「下一节」按钮文案、是经哪一层（`text` / `class` / `toc`）认出来的、以及
  它是「下一节」还是「下一章」。页面上一旦全是 `⚠`，就说明这个页面上确实没有翻节按钮。

`tools/tab-test.mjs` 的 `nextbtn` 场景把六种写法逐个锁死，另外放了四个诱饵
（「下一节的测验」「请先完成下一节的任务点」「下一章节」「返回上一节」）
确认不会被误点。

测试见 `tools/tab-test.mjs` 的 `chain` 场景：三节（第 2 节有测验、第 3 节没有），
断言「点了 2 次下一节、没点那个『下一章』、恰好 5 道题、一次都没切回视频标签」。

## 八、翻页抓取为什么容易抓不全

`autoPage` 的终止条件曾经写错过一次，症状是「点整卷翻页抓取，翻两页就自己停了」。
两个原因叠在一起：

**原因一：把「这一页没抓到新题」当成了终点。**
分页作业里本来就可能夹着没有题目的说明页；而且下一页只要渲染慢一点，
扫描扫到的还是上一页的内容，一样会被判成「没新题」。这条规则已经删掉了。

**原因二：用固定 900ms 的 sleep 等下一页。**
下一页要 1.5 秒才渲染完就必然扫到旧内容。

现在的等待逻辑分三层：

```
点击「下一题」
   │
   ├─ 轮询页面指纹，直到它和点击前不一样        （等"变了"）
   │
   ├─ 指纹连续 stableMs 不变才算渲染完           （等"稳定"）
   │     · 页面上已有题目块 → 500ms
   │     · 还没有题目块（加载占位符）→ 2000ms
   │     · 有加载遮罩 → 不算稳定，继续等
   │
   └─ 再扫描，然后判断要不要继续
```

第三层是关键。光等「内容变了」不够 —— 超星翻页是两段式的，
先清空容器显示「加载中」，过一两秒才把题填进去。
那段占位符本身是很稳定的，用统一的稳定窗口会在占位符阶段就判定「渲染完了」，
扫到一张空页面。所以稳定窗口要按「这页现在长什么样」动态取。

页面指纹也不是只看题干 —— 翻到说明页时题干是空的，看题干会误判成「没换」。
实际用的是：题目块文本 → 没有题目块时退化成整页文本 → 再加分页指示器和 iframe 的 src。

这四个场景有专门的回归测试（`tools/paging-test.mjs`），改 `autoPage` 后必跑。

## 九、超星改版了怎么修

抓不到题目时，**只改 `extension/src/content/extractor.js` 顶部的 `SEL` 对象**：

```js
var SEL = {
  block:      ['.TiMu', '.questionLi', ...],   // 单题容器
  typeLabel:  ['.fl.letter', ...],             // 题型标签
  stem:       ['.Zy_TItle .clearfix', ...],    // 题干
  optionList: ['.Zy_ulTop li', ...],           // 选项
  answerBox:  ['.Py_answer', '.mark_answer', ...],  // 答案区
  noise:      [...]                            // 要从题干里剔除的噪音
};
```

排查步骤：

1. 在作业页按 F12，选中一道题的外层容器，记下它的 class
2. 打开控制台执行 `CQBExtractor.scanDocument()`，看 `stats` 里 `blocks` 和 `parsed` 各是多少
   - `blocks: 0` → 改 `SEL.block`
   - `blocks > 0, parsed` 偏少 → 看 `SEL.stem` / `SEL.optionList`
   - 题目对了但没答案 → 看 `SEL.answerBox`，或页面本来就还没公布答案
3. 改完在 `edge://extensions/` 点扩展的刷新按钮，再刷新作业页

## 十、开发与测试

```bash
# 1) 改完 site/ 下的源码后，同步到扩展包（必做）
node tools/sync-practice.mjs

# 2) 逻辑测试：判分 / 去重 / 合并 / 导入 / 会话引擎，共 72 项
node tools/smoke-test.mjs

# 3) 界面集成测试：用真实 Edge 无头模式跑完整交互，共 113 项
node tools/browser-test.mjs

# 4) 翻页抓取回归：五种分页场景（改 autoPage 后必跑）
node tools/paging-test.mjs

# 5) 章节测验标签自动切换 + 连续采集本章（改 findQuizTab / startChapterHarvest 后必跑）
node tools/tab-test.mjs

# 6) 重新生成图标（纯 zlib 手写 PNG，无第三方依赖）
python tools/make-icons.py
```

**注意**：`extension/src/practice/` 和 `extension/src/shared/schema.js` 都是生成物，
不要直接编辑，改了会在下次同步时被覆盖。

冒烟测试里有两项专门校验「副本与源文件一致」，忘了同步会直接测失败 —— 这是故意的。

### 测试为什么分三层

| 层 | 文件 | 覆盖 | 成本 |
|---|---|---|---|
| 逻辑 | `smoke-test.mjs` | 纯函数（判分/去重/合并/导入/会话引擎/学科归组）+ **发布护栏** | `node:vm` 沙箱，零依赖，约 1 秒 |
| 界面 | `browser-test.mjs` | 点击、键盘、localStorage、CSS 生效、状态流转、学科筛选/改名/归类 | 真实 Edge 无头，约 5 秒 |
| 翻页 | `paging-test.mjs` | `autoPage` 在空页/慢页/假按钮/按钮变灰/中途中止下的行为 | 5 个场景，约 15 秒 |
| 标签 | `tab-test.mjs` | 章节测验自动切换 + 连续采集本章 + 「下一节」六种写法 + 停止按钮复位 + 抓取按钮防卡死 | 6 个场景，约 15 秒 |

四套合计 542 项断言，跑完约 30 秒。

每次运行都会建一个独立的临时目录（`tools/.tmp/<测试名>-<时间戳>/`），跑完自动删掉。
排查问题时用 `KEEP_TMP=1` 或 `NO_CLEAN=1` 保留下来，直接用浏览器打开里面的
`page-*.html` 就能复现。

`tab-test.mjs` 特别值得一提：它用 `tools/lib/chrome-stub.js` 伪造了 `chrome.runtime`
和 `chrome.storage`，让 **content.js 本身**能在普通网页里跑起来。所以测的不只是
提取器的纯函数，而是「首次自动扫描 → 决定要不要切标签 → 真的点了 → 抓到题 →
发 CAPTURE → 切回原标签」这整条链路。

后两层共用一个 `tools/lib/headless.mjs`：把页面拷到临时目录、追加测试脚本、
用 `msedge --headless=new --dump-dom` 打开，再从转储的 DOM 里把结果抠回来。
**不需要装 puppeteer 或 playwright。**

之所以不用 jsdom：这些页面重度依赖真实的事件派发时序、`classList`、
`getComputedStyle` 和 Promise 微任务顺序，jsdom 在这些点上和浏览器有偏差 ——
以下三个 bug 全都只有真实浏览器才测得出来：

| 被测试抓出的 bug | 根因 | 修法 |
|---|---|---|
| 答错后点「错题」标签是空的 | 进度写入有 150ms 防抖，但筛选时回读了尚未落盘的 localStorage | `Session.buildPool()` 改为从调用方接收内存中的 progress，不再自己读 storage |
| 多条提示气泡叠成一团糊字 | 每条提示都独立 `position: fixed` 到同一坐标 | 统一挂进一个 `flex-direction: column` 的容器，自然往下排，最多留 4 条 |
| **任务结束后点「停止抓取」没反应** | `stopPaging` 从不复位面板；`stopChapterHarvest` 又在「没在跑」时**提前 return，把界面复位一起跳过了**。于是撞到上限自动停下之后再点停止，界面纹丝不动 | 复位改成**无条件**：`resetTaskUI()` 先跑，再去通知后台；`stopChapterHarvest` 把 `setPagingUI(false)` 提到判断之前。另加看门狗兜底「任务结束但收尾消息丢了」的情况 |
| 点收藏后按钮不变色 | 同上，`doStar()` 里 `STATE.progress = Store.loadProgress()` 读到旧值 | 直接用 `toggleStar()` 就地修改后返回的条目 |
| 提交后按钮写着「重新提交」但点了没反应 | 选项在提交后被锁定，重新提交等于重复记录一次作答，是纯噪音 | 按钮改为「重做本题」，行为切到 `doRedo()` |

改 UI 相关的代码后跑 `browser-test.mjs`；改 `autoPage` 后跑 `paging-test.mjs`。
两者都会打印失败明细并保留临时目录，可以直接用浏览器打开手动复现。

翻页测试的四个场景定义在 `tools/fixtures/paged-quiz.html`，
它模拟了超星的两段式渲染（先清空再填充）、没有题目的说明页、和点了没反应的假按钮。

浏览器路径会自动探测；装在非默认位置时用环境变量指定：

```bash
EDGE_PATH="D:\path\to\msedge.exe" node tools/browser-test.mjs
KEEP_TMP=1 node tools/paging-test.mjs    # 保留临时目录，便于手动复现
NO_CLEAN=1 node tools/tab-test.mjs       # 同上（不想删目录时用这个）
```

## 十一、已知限制

1. **只解析 DOM，不调接口。** 超星的作业详情接口有加密签名，逆向成本高且容易失效。DOM 方案的好处是跟着页面走，页面能看到的就能抓。
2. **考试中的试卷抓不到答案。** 这是理所当然的 —— 答案要提交后才发布。扩展能抓的是题干和选项，用于考后复盘。
3. **公式以 HTML 形式保存。** 超星用的图片公式会被正确保留；MathJax 渲染的公式依赖源页面的 MathJax 上下文，可能降级为原始文本。
4. **简答题不自动判分。** 语义匹配误判率高，宁可让用户自己对参考答案。
5. **仅在作业 / 考试作答页有效。** 课程目录页、视频页、资料页没有题目，扩展会明确提示而不是给个空结果。
6. **题库不跨设备同步。** 数据只在本机。需要带走就导出 JSON —— 这也是为什么导出格式设计得比较严谨。
